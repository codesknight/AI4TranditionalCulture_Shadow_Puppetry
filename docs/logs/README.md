# 项目日志

所有日期按 Asia/Shanghai 记录。日志跟随代码提交维护，保留事实、验证结果与未完成项，不把计划写成完成记录。

| 文件 | 内容 |
| --- | --- |
| [需求日志](requirements.md) | 用户诉求、范围、验收条件、需求状态 |
| [开发日志](development.md) | 实现内容、设计选择、影响与后续工作 |
| [测试日志](testing.md) | 环境、命令、结果、覆盖范围与验证限制 |
| [Bug 排查日志](bugs.md) | 现象、复现、根因、修复、回归与状态 |
| [架构设计](../架构设计.md) | 模块边界、数据结构、扩展方法 |
| [双人对战需求草案](../双人对战需求草案.md) | 用户要求保留的待开发对战方案 |

## 维护规则

- 需求使用 `REQ-xxx`，缺陷使用 `BUG-xxx`，开发记录使用 `DEV-xxx`，测试批次使用 `TEST-xxx`，编号保持唯一。
- 开工先明确需求与验收条件；实现与测试过程中持续更新相应日志。
- 每个功能或缺陷提交包含对应日志更新。无新缺陷时不虚构 Bug；测试未运行或被环境阻塞时明确记录。
- 记录日期、关联编号、实际变更、证据与待办。可使用提交主题关联记录，避免为了写入当前提交 SHA 产生无意义的追补提交。
- 旧记录保留；修正历史信息时说明原因，不把后来推断伪装成当时观察。
- 不写入访问令牌、密码、隐私信息或完整环境密钥。
