# 皮影游乐场架构设计

更新日期：2026-11-17，关联 REQ-002、REQ-004、REQ-005。

## 目标与边界

以独立的光源、影幕、影偶、操纵杆组成可交互场景。保持零运行时依赖、可直接打开 HTML；使用普通数据对象、纯计算与少量适配器，不引入继承树或通用游戏引擎。当前支持一个影偶和三根签杆，多影偶尚未实现。

## 数据与模块

```text
输入 / 工具箱 / 动画帧
          ↓ 命令
    model → State { scene, game, action, playing, time, speed, selectedId }
                 ↓
    actions → kinematics → projection → renderer → SVG / HUD
                 ↑             ↑
              puppet     lightSource / screen / rods
```

| 模块 | 职责 |
| --- | --- |
| `config.js` | 舞台、臂长、控制范围及签杆描述 |
| `entities.js` | 四类对象工厂、属性白名单、查找、不可变更新、快照深冻结 |
| `actions.js` | 动作元数据与姿态采样策略，同时驱动 UI |
| `kinematics.js` | 动作姿态、定长手臂 IK、朝向与坐标变换、签杆关节锚点 |
| `projection.js` | 点光源投影矩阵、投影后关节与签杆手柄位置 |
| `game.js` | 关卡目标、匹配计算、保持判定、计时、得分与终局 |
| `model.js` | 状态命令转换、跳跃积分、对象操作、订阅 |
| `renderer.js` | 影人/目标影子/签杆/灯/影幕/过关粒子的 SVG 表现 |
| `controller.js` | DOM 事件、键盘状态、指针捕获、工具箱与 HUD、本机最佳成绩存取 |

经典脚本按 HTML 的 `defer` 顺序加载，共享唯一命名空间 `ShadowTheatre`；Node 通过 CommonJS 测试同一核心代码。保留直接打开本地 HTML 的能力。

## 四类独立对象

`Scene = { lightSource, screen, puppet, rods[] }`，每个对象都有稳定 `id` 与 `type`。

| 对象 | 属性 | 独立操作 |
| --- | --- | --- |
| LightSource | `x, y, intensity, softness, color` | 拖动位置、亮度、柔度、三种光色 |
| Screen | `x, y, depth, material` | 拖动/滑杆位移、距离、三种幕面风格 |
| Puppet | `x, y, velocityY, liftL, liftR, depth, facing` | 移动、跳跃、转身、手臂角度、离灯距离 |
| Rod | `puppetId, joint, field, label, offset, length, visible` | 每根独立调整长度与显隐，通过手柄驱动关联关节 |

对象通过 `UPDATE_OBJECT { id, patch }` 更新，只接受对应类型白名单属性。无效数值、未知属性、继承属性和未知 ID 被忽略，数值按上下界裁剪；朝向仅允许 ±1。更新一根签杆保留其他对象的引用。签杆按 `puppetId`、`joint` 描述连接关系；当前单影偶实现按命名关节求锚点，不依赖数组顺序。状态快照递归冻结，防止意外改写嵌套对象。

跳跃的高度和速度由模型维护，不对外暴露任意编辑；不能在空中重复叠加跳跃。

## 投影模型

简化设置光源深度为 0，影偶与幕面分别处于正深度。所有可调范围满足 `0 < puppet.depth < screen.depth`。

```text
m = screen.depth / puppet.depth
screenPoint = lightPosition + m × (worldPoint - lightPosition)
displayPoint = fit × screenPoint + displayOrigin × (1 - fit) + screenOffset
```

其中 `fit = 0.78` 为显示适配比例，非物理参数。灯位改变影子位移；影偶靠灯或幕面远离灯时影子变大。模糊度以 `softness × (m - 1)` 近似；幕布材质和灯光色调通过独立 CSS 变量组合。此处是互动教学近似，不声称复现真实皮料、面光源、投影遮挡和透光率。

真实影偶姿态、目标影子、判分关节和杆件锚点使用同一投影计算，避免画面与判分坐标不一致。

## 游戏结构

`Game = { status, level, score, bonus, combo, remaining, hold, match, event }`。

- 状态：`idle → playing ↔ paused → won / lost`，可重新开始或退出到自由戏台。
- 五个关卡以普通对象描述目标位置、手臂角度、深度与朝向；目标场景由新工厂对象构建，不改写当前场景。
- 用投影后的双手与躯干锚点平均距离计算匹配度；朝向错误或亮度低于 45 时匹配度为 0，并提示修正。
- 自由操偶状态下达到 86% 匹配度并连续保持 0.65 秒过关；中断对齐会清零保持进度。
- 每关得分为 `100 + 连续过关数 × 20`；五关基础总分 800，通关再获得 `ceil(剩余秒数) × 2` 的时间奖励。
- 75 秒倒计时按前台实际帧间隔扣减；动画、键盘位移、跳跃积分和保持判定使用最多 0.05 秒的单步增量，避免长帧瞬移或瞬间判定过关。
- 页面隐藏自动停止推进，恢复时重置时间基准；显式暂停冻结计时/动作帧，仍可整理对象参数，恢复后继续判分。
- 最佳分数保存在本机 `localStorage`；访问失败时不阻断游戏，不涉及服务器或账户。

## 输入与扩展

键盘 `A/D` 平移，`W` 跳跃，`F` 转身，`Q/E` 左手，`O/P` 右手。方向键可微调聚焦的 SVG 手柄、灯和幕面；输入控件保留原生键盘行为。快捷按钮和滑杆提供触屏替代操作。失焦、页面隐藏或切换模式时清理按键/拖动会话并释放指针捕获。

新增动作仅扩展 `ACTIONS`；新增关卡扩展 `LEVELS`。新增对象属性先补充工厂、属性规则，再接工具箱与测试。若将来扩展多影偶，应将 `Scene.puppet` 演进为角色集合，并按 `puppetId` 解析对应实体；当前不虚构已经具备此能力。

交互手柄使用稳定节点和按 ID 的映射保留焦点。影人装饰性 SVG 字符串更新仍保留，这是当前规模下的简单实现。测试通过真实 HTML 的 ID/属性建立 DOM 边界替身，覆盖事件连接，不能替代真实浏览器视觉和触摸验收。
