# 皮影展示 Demo 架构设计

更新日期：2026-11-17。适用于本轮模块化重构后的实现。

## 目标与取舍

保持静态网页、零运行时依赖、可直接打开 HTML 的使用方式；将变化频繁的动作、状态、计算、绘制和输入分开。当前只有一个影人、六种操作模式，使用普通对象和小数组即可，不引入组件框架、事件总线、类继承体系或通用骨骼引擎。

## 模块边界

```text
DOM 事件 → controller → command → model/store
                                   ↓ 状态快照
                       actions → kinematics → renderer → SVG
                          ↑           ↑           ↑
                          └──────── config ────────┘
```

| 文件 | 职责 | 不应承担的职责 |
| --- | --- | --- |
| `demo/core/config.js` | 舞台原点、肩关节、臂长、控制限值与签杆描述 | DOM 操作 |
| `demo/core/actions.js` | 动作元数据与采样函数 | 事件监听、计时器、直接渲染 |
| `demo/core/model.js` | 初始状态、命令转换、快照订阅 | 依赖 DOM 或真实时钟 |
| `demo/core/kinematics.js` | 动作求姿态、手臂约束、坐标转换与拖动映射 | 修改应用状态、绘制 SVG |
| `demo/core/renderer.js` | 将姿态转换为 SVG，维护稳定的交互节点 | 决定播放和交互规则 |
| `demo/controller.js` | 组合模块，绑定事件，驱动动画帧与界面 | 定义动作算法 |

浏览器用有序 `defer` 经典脚本加载，模块通过唯一命名空间 `ShadowTheatre` 组合；Node 测试通过 CommonJS 导入同一份核心源码。这样保持 `file://` 直接打开能力。暂不迁移到原生 ES Module，因为后者在本地文件访问下可能受浏览器跨源限制。

## 使用的设计方式

1. **动作策略**：每个动作是带 `sample(pose, time)` 的普通对象。注册表同时驱动按钮文案与动作计算，新增动作不需要增加多个 `if` 分支。
2. **显式状态转换**：`transition(state, command)` 返回新状态；无效命令保持原状态。规则可以直接单元测试。
3. **轻量订阅**：`createStore()` 仅提供 `getState / dispatch / subscribe`，用 `Set` 保存监听函数并支持取消订阅。当前只有一个视图订阅者。
4. **计算与适配分离**：关节计算只处理数据；渲染器和控制器处理 DOM。无需为这些职责建立继承层次。

## 核心数据结构

| 数据 | 结构 | 约束 |
| --- | --- | --- |
| `State` | `{ action, playing, time, speed, x, liftL, liftR, light, showRods }` | 扁平、可序列化，提交后快照冻结；角度为度，时间为秒 |
| `Action` | `{ id, name, icon, subtitle, title, note, animate, sample }` | `id` 唯一，文案和采样逻辑在同一处维护 |
| `Command` | `{ type, ...payload }` | 类型包括选择动作、播放切换、控制调整、设置调整、帧推进和归位 |
| `Point` | `{ x, y }` | SVG 逻辑坐标，和 CSS 像素区分 |
| `Pose` | `{ x, y, lean, step, left, right, arms, rods }` | 每次从状态重新计算，不存回状态 |
| `Arm` | `{ shoulder, elbow, hand }` | 上臂、前臂长度均等于配置臂长，超出可达范围的手部目标投影回可达圆 |
| `Rod` | 签杆描述加 `{ anchor, handle }` | 固定三根签杆，小数组便于确定绘制次序 |
| `DragSession` | `{ field, value, start, pointerId }` 或 `null` | 仅控制器持有，忽略第二个指针，结束时释放捕获 |

动作注册表只有六项，使用数组查找，避免同时维护顺序数组和索引映射。帧状态不包含 DOM、函数或计时器句柄；动作策略中的函数与运行状态分开。

## 行为约定

- 手动调整停止预设动作，回到自由操偶模式。
- 归位重置动作、时间和身体/手臂位置，保留灯光、速度与签杆显示偏好。
- 暂停或页面隐藏时不推进动作时间；恢复可见时重置帧基准，单帧增量最多 0.05 秒，避免长时间切换后跳帧。
- 非有限数值被忽略，有限数值按配置限值裁剪。未知动作、字段与命令被忽略。
- 手柄 DOM 节点只初始化一次；逐帧更新其位置与可访问性数值，保留焦点和节点身份。影人装饰性 SVG 目前每帧更新字符串，这是本规模下有意保留的简单实现。
- 页面中文以 UTF-8 存储。样式通过 Prettier 格式化；保持低依赖和可读性。

## 如何扩展

新增动作时，在 `actions.js` 的 `ACTIONS` 数组添加一个具有完整元数据的对象，提供 `sample(pose, time)`。函数只修改本次传入的姿态，不读取 DOM，也不修改状态。按钮自动生成，现有批量几何测试自动遍历新动作；再补充该动作的特有行为断言。

新增控制项时，先补充配置与状态字段，再在 `transition` 定义允许的命令和边界规则；最后接入控制器与界面。不要直接从事件监听器修改状态对象。

新增影人或复杂骨架尚未实现。若出现多角色需求，再将当前关节常量与造型资源抽取成角色配置，并在需求日志记录设计变更，避免为未确认需求预先建立复杂引擎。

## 验证与交付

`npm run verify` 执行格式检查、JavaScript 语法与 HTML 本地资源检查、单元/控制器测试、静态打包。GitHub Actions 在 `main` 推送与 Pull Request 时运行同一命令。自动化测试中的 DOM 替身不能验证浏览器布局、真实指针捕获或移动端手势。
